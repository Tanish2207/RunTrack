## History

- [ ] With a real account, Save Run, Cycle, and Walk activities. History lists
  only that owner's latest 50 activities, newest-first, with correct type icons,
  local dates, distance, duration, and average pace.
- [ ] Save a new activity and return to History. The first snapshot/refocus
  updates the list without restarting the app or creating duplicate listeners.
- [ ] A new account with no activities gets the empty state and a working
  **Go to Track** action, not an endless spinner.
- [ ] Delay the first snapshot: the list section shows loading. Fail the read
  (network, invalid configuration, or unavailable index): inline error/toast
  is actionable, Retry resubscribes, and success replaces the error.
- [ ] The owner query runs against the deployed `userId ASC / startTime DESC`
  composite index without an index error. Mocked query tests are not proof.
- [ ] Switch tabs, enter Detail, and return repeatedly. Listener cleanup and
  refocus leave one active History subscription, no hidden-screen error toasts,
  and no leaked updates after unmount/logout.
- [ ] On iOS the large History title collapses when scrolling. On Android and
  web the list remains scrollable without nested-list warnings or clipped rows.
- [ ] The reserved sync slot keeps the same single-line footprint while
  loading, empty, failed, and populated. It is blank and inaccessible until
  #017; no fabricated pending-sync count is shown.
- [ ] Small screens, large font settings, and screen readers can access each
  row's metrics and its Detail action without truncated essential values.

## Detail and owner isolation

- [ ] Tap each activity type. The URL carries its actual activity ID, Back
  returns to History, and a direct valid Detail link has the History anchor.
- [ ] Detail displays the exact stored stats, type, local date/time, and
  type/date header—not values recalculated from a live tracking session.
- [ ] On both native platforms, the map initially fits the stored route and
  Start/Finish markers with padding, then remains pannable/zoomable. Reviewing
  a saved activity does not request location permission or start a GPS watch.
- [ ] Verify a zero-point route gives an honest notice and a one-point route
  centers safely. The saved route is flat; exact pause boundaries are not
  reconstructed. Segmented pre-save review remains covered by tracking QA.
- [ ] Detail shows a stored nonblank `aiSummary` in the shared recap card.
  Missing/blank recap has no AI card or fake generation spinner. Refocusing
  Detail reads a later stored recap update.
- [ ] Missing/invalid IDs, deleted activities, and another owner's ID give a
  non-revealing not-found state. Retry works for ordinary read failures.
- [ ] Sign out/switch accounts while History or Detail reads are pending and
  while retaining old row/Retry handlers. No old-owner row, route, recap, title,
  toast, or late navigation appears in the new account.
- [ ] Change the Detail ID or leave before a read settles. Old success/error
  cannot replace the current activity or retitle/toast an inactive screen.
- [ ] Both screens remain read-only: no edit/delete, elevation, social,
  wearable, or health integrations.
- [ ] Web displays the informational native-map fallback while retaining
  functional list, stored stats, and recap/error states.

## Verification limits

Vitest checks repository mocks, controlled hooks, JSX props, and imperative map
calls. These do not render a native list/map, exercise React scheduling, perform
real Router transitions, or enforce deployed Firebase security rules. Production
exports verify bundling only, not device boot or any checkbox above.

complete hrefs used by both screens — including the required `activityId` param
on the Detail route — against the current route tree; they are git-ignored and
regenerated by `expo start`/`expo export`, and they are not runtime navigation
proof. Latest automated run (2026-11-16): `npx expo lint`, strict

**20/20**, and a fresh Android Hermes export all pass.
